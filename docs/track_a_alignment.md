## Deliverable mapping

| Expected element | This repository |
| --- | --- |
| Real disaster case studies | Three, built by scripts under [`scripts/`](../scripts/) through the harness: Eaton Fire 2025 ([`events/eaton-2025/`](../events/eaton-2025/)), Hurricane Milton 2024, Hurricane Ian 2022. A fourth, Super Typhoon Bavi 2026, was captured live pre-landfall and is archived under `events/archive/bavi-2026/`. |
| Vulnerability analysis | CDC SVI 2022 joined to the Eaton damage grid at H3 r9 across 20 Census 2020 tracts, with the downscaling approximation declared per feature ([`scripts/build_eaton_svi.py`](../scripts/build_eaton_svi.py)). |
| Exposure analysis | 18,428 CAL FIRE DINS structure points → a 265-cell H3 r9 damage grid with per-severity counts and mandatory uncertainty fields; 5,618 Pinellas County cells carrying county debris-program volumes with Milton wind/rain covariates; per-tile 2020 Census population for all three AOIs ([`scripts/build_population.py`](../scripts/build_population.py)) with centroid allocation and pre-event vintage declared per feature. |
| Resilience / decision relevance | Planner mode weights structural damage against social vulnerability on a live trade-off slider; the resulting tile priorities are recomputed client-side from the published grids. Budget-constrained inspection routing is **not implemented**. |
| Geospatial method depth | H3 r9 aggregation with declared downscaling, reliability-gated cross-view matching, statistical-power declarations for small classes (`damaged_repairable`, n=30, declared rather than hidden). |
| AI component | An LLM risk analyst behind the Steward Harness ([`src/geosteward/gateway/`](../src/geosteward/gateway/)): deterministic request classification, policy pre-check, evidence retrieval, generation, claim post-check, audit. The model never decides its own authorization. Provider-agnostic; local Ollama by default. |
| Accountability / verifiability | Two policy planes in [`policy_v1.yaml`](../src/geosteward/harness/policy_v1.yaml) — claim and distribution — plus append-only audit logs, SHA-256 manifests, and a CI gate that verifies the assembled public site against the distribution plane. A third axis, `verifiability` (`retained` > `re-derivable` > `cited-only`, weakest-link), states what a *reader* can do to check a claim, and a `license` attribute denies redistribution of third-party content by rule. |
| Accountability without retention | The one contribution here that is not an application of existing practice: GMP terms forbid retaining Maps Content, which is structurally incompatible with proving traceability by hashing every input. [`live/`](../src/geosteward/live/) resolves it by attesting to the *request* plus a response digest — publishable because it holds no content — with a containment property test as the enforcement. Design and implementation notes: [`design/specs/2026-08-20-non-retainable-evidence-design.md`](design/specs/2026-08-20-non-retainable-evidence-design.md). **Never executed against Google:** no API key, so both adapters are tested against an in-process stub. |
| Reproducibility | 266 Python tests + 44 app tests in CI; timestamped API snapshots; pinned build scripts. **Limitation:** the deep-case builders read a ~33 GB corpus on the maintainer's workstation, so `events/` cannot currently be regenerated by a third party. The committed artifacts, their hashes, and their audit logs are what a reviewer can verify today. |
| Honest negative results | The append-only audit logs preserve a stage the harness rejected and forced to be corrected, and [`incidents/2026-08-20-publication-boundary.md`](incidents/2026-08-20-publication-boundary.md) documents a constraint this project stated and then violated in its own deployment. |

## What is absent

Listed so a reviewer does not have to discover it:

- No hosted agent gateway. The public site has no chat backend, and the gateway
  has no auth, rate limiting, or log redaction (see `Next` in [`STATUS.md`](STATUS.md)).
- No live third-party lookup has ever run. The `re-derivable` regime is
  implemented, policed, and tested against a stub; `events/live_evidence.jsonl`
  does not exist outside tests because there is no API key. The mechanism is
  demonstrable in code and in the test suite, not on the public site.
- No inspection-routing or budget-allocation output.
- `watch_status.json` publishes per-source health and skipped features; the app
  does not yet display them.
- No tagged release, CHANGELOG, CITATION.cff, or contributor documentation.
